# 4-0. オペレーターとは

## この回で学ぶこと
- R3 における「オペレーター」とは何かを理解する
- LINQ 形式（メソッドチェーン）で処理を記述する考え方を理解する
- 次回以降で個別のオペレーター（Where, Select, Take など）を学ぶための土台を作る

## 前提知識
- Unit3 で学んだ ReactiveProperty / Observable / Subscribe の基本
- C# の LINQ（`Where`, `Select` など、配列や `List<T>` に対して使うメソッド）に触れたことがあると理解が早いですが、必須ではありません

## 概念解説
R3 では、Observable の流れに対して「加工」を行うために **LINQ 形式**でコードを書きます。LINQ 形式とは、`.Where(...)` や `.Select(...)` のような「オペレーター」と呼ばれるメソッドを、`.` でどんどんつなげていく書き方です。

これは、**ベルトコンベア上の工程**をイメージするとわかりやすいです。工場のベルトコンベアに材料（＝データ）が流れてきて、

1. 不良品を弾く工程（`Where`：条件に合わないデータを弾く）
2. 形を加工する工程（`Select`：データを別の形に変換する）
3. 一定数だけ通す工程（`Take`：決まった回数だけ流したら止める）

のように、複数の工程（オペレーター）を順番に並べておくと、材料は工程を通るたびに少しずつ加工され、最後に完成品として `Subscribe` に届きます。それぞれの工程（メソッド）は「前の工程の結果」を受け取り、「次の工程に渡す結果」を返すだけなので、工程を増やしたり並び替えたりしても、全体の流れを崩さずに処理を組み立てられます。

これにより、複雑な条件分岐やループを使わなくても、**数行のメソッドチェーンで「データがどう加工されて届くか」を宣言的に書ける**のが LINQ 形式・オペレーターの大きな利点です。次回以降、このベルトコンベアに具体的な工程（オペレーター）を追加していきます。

## よくあるつまずきポイント
- オペレーターを「特別な構文」だと身構えてしまいますが、実態はただの C# メソッド（拡張メソッド）です。難しく考えすぎないようにしましょう。
- メソッドチェーンの**順番**を変えると結果が変わることを軽視しがちです（例：先に `Take(3)` してから `Where` するのと、先に `Where` してから `Take(3)` するのとでは意味が異なります）。この点は次回以降、具体例で確認します。
- 「オペレーターを使うと元のデータが書き換わる」と誤解しがちですが、実際には元の Observable の流れはそのままで、新しい流れが都度作られていきます。
