# 3-0. ReactivePropertyとは

## この回で学ぶこと
- `ReactiveProperty<T>` が「値を持つ変数」と「Observable（値の変化を通知する仕組み）」を合体させたクラスであることを理解する
- 通常の変数・プロパティとの違い（自動通知・重複通知の抑制）を理解する
- 次回以降で実際にコードを書く前に、ReactiveProperty のイメージを掴む

## 前提知識
- Unit1〜2 で学んだ `Observable`・`Subject`・`Subscribe`・`AddTo` の基本的な使い方
- C# のプロパティ（`get`/`set`）の基本文法

## 概念解説
今までの Unity のスクリプトでは、「HP が減った」「スコアが増えた」といった変化を他のスクリプトに伝えるために、`Update()` の中で毎フレーム値をチェックしたり、専用のイベント（`UnityEvent` や C# の `event`）を自分で用意したりする必要がありました。

`ReactiveProperty<T>` は、この「値の変化を誰かに知らせる」という仕組みを最初から内蔵した特別な変数です。たとえるなら、**値が変わるたびに自動で店内放送をしてくれる値札**のようなものです。値札（＝ReactiveProperty）に新しい値段を書き込むと、その場でお店中に「値段が変わりました」と放送（＝通知）が流れ、放送を聞いている人（＝Subscribe している側）はすぐに新しい値段を知ることができます。わざわざ誰かが値札を見に行って確認する必要はありません。

ReactiveProperty は Rx（Reactive Extensions）の特別なクラスで、`Subject` と同じように Observable を継承しているため、`Subscribe` で購読するという基本の使い方はこれまでと同じです。ただし、Subject と違って `OnNext` メソッドは存在しません。値を変えたいときは `.Value` に代入するだけで、その変化が自動的に通知される仕組みになっています。

さらに、ReactiveProperty には便利な最適化が入っています。**同じ値をもう一度代入しても通知は発生しません。** 例えば HP が 100 のときに `.Value = 100` と再代入しても、何も変わっていないので放送は流れません。これにより、UI の再描画や重い処理を無駄に走らせずに済みます。

## よくあるつまずきポイント
- 「ReactiveProperty はただの変数」と誤解し、`Subscribe` しなければ何の意味もないことを忘れてしまう（通知を受け取る側がいて初めて価値が生まれます）
- 「値を書き換えるたびに必ず通知が来る」と思い込む（同じ値を再代入した場合は通知されないことに注意）
- ReactiveProperty と Subject を混同する（Subject は「流す専用」で値を保持しない一方、ReactiveProperty は現在の値を保持し続ける点が異なります。詳しくは次回以降で扱います）
