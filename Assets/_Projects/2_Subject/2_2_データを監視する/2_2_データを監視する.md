# 2-2. データを監視する

## この回で学ぶこと
- 別のクラスが持つSubjectを、`Subscribe`を使って監視（購読）する方法を身につける
- `[SerializeField]`でInspector経由でコンポーネント同士を紐付ける書き方を復習する
- 前回「発行しても何も起きなかった」Subjectに、Observerを追加することでデータが流れ始める様子を確認する

## 前提知識
- 「2-1. データを発行する」で作った、`Subject<int>`と`OnNext`によるデータ発行の仕組み
- `[SerializeField]`でInspectorから他のコンポーネントを参照する書き方
- `Subscribe`の基本的な使い方（1-1、1-2レッスンで経験済み）

## 概念解説
前回、`SampleSubject`は毎フレーム`OnNext`でデータを発行していましたが、それを受け取るObserverがいなかったため、Consoleには何も表示されませんでした。今回はいよいよ、そのSubjectを**監視する側（Observer）**を実装します。

Subjectでデータを監視するには、`Subscribe`メソッドを使ってObserverを登録します。これにより、Subjectが発行するデータを受け取れるようになります。Observerは、データが発行されるたびにその通知を受け取り、必要に応じて処理を実行します。

今回のポイントは、**発行する側（`SampleSubject`）と監視する側（`SampleObserver`）が、別々のクラス・別々のコンポーネントとして分かれている**ことです。実際のゲーム開発でも、「データを発行する係」と「そのデータを使って画面を更新する係」を分けて設計することがよくあります。Subjectを使うと、この2つの役割をきれいに分離して書けるようになります。

## シーンの操作方法
1. Playボタンを押してシーンを実行します。
2. 前回とは異なり、今回はConsoleに`frame: 0`、`frame: 1`、`frame: 2`...という連番のログが毎フレーム流れ続けるのを確認してください。
3. Hierarchyの`Scripts`オブジェクトを選択し、Inspectorで`SampleObserver`コンポーネントの`Target`欄に、同じ`Scripts`オブジェクト上の`SampleSubject`が設定されていることを確認しましょう。この参照があるおかげで、`SampleObserver`が`SampleSubject`の`UpdateSubject`にアクセスできています。

## コード解説
発行する側（`SampleSubject`、前回から変更なし）：
```csharp
public Subject<int> UpdateSubject { get; } = new();
```

監視する側（今回新しく追加する`SampleObserver`）：
```csharp
public class SampleObserver : MonoBehaviour
{
    [SerializeField] private SampleSubject _target;

    private void Awake()
    {
        // UpdateSubjectを購読する
        _target.UpdateSubject
            .Subscribe(x =>
            {
                // OnNextが呼ばれた時の処理
                Debug.Log($"frame: {x}");
            })
            .AddTo(this); // このコンポーネントが破棄されたら購読を解除
    }
}
```
- `[SerializeField] private SampleSubject _target;`：Inspector経由で、発行する側の`SampleSubject`コンポーネントを直接受け取っています。これにより、コード上から`_target.UpdateSubject`という形でSubjectにアクセスできるようになります。
- `_target.UpdateSubject.Subscribe(x => { ... })`：`_target`が持つ`UpdateSubject`を購読しています。ラムダ式の引数`x`には、`SampleSubject`側で`OnNext(_count++)`によって発行された`int`値がそのまま渡ってきます。
- `.AddTo(this);`：ここでは観測対象（`_target`）ではなく`this`（`SampleObserver`自身）が渡されています。1-1レッスンで学んだ「観測対象のライフサイクルに合わせる」考え方に対して、こちらは「自分（購読している側）が破棄されたら、自分の購読も解除する」という、より一般的な使い方です。どちらを選ぶかは「何が壊れたときに購読を止めたいか」で判断します。

## 実行結果の例
```
frame: 0
frame: 1
frame: 2
frame: 3
...
```
毎フレーム1ずつ増える整数がConsoleに流れ続けます。Play直後から数値がどんどん増えていく様子を確認しましょう。

## よくあるつまずきポイント
- Inspectorで`SampleObserver`の`Target`欄に`SampleSubject`を割り当て忘れると、`NullReferenceException`が発生します。エラーが出たら、まずInspectorの参照設定を確認しましょう。
- 「`SampleSubject`と`SampleObserver`、どちらが先に動くのか」を意識せずに読むと混乱します。`SampleSubject`は`Start`で`AddTo`だけを行い、`Update`で発行を始めるのに対し、`SampleObserver`は`Awake`の時点で先に購読を済ませています。Unityのイベント呼び出し順（`Awake`→`Start`→`Update`）を意識すると、「購読が先に完了してから発行が始まる」という流れが理解しやすくなります。
- `.AddTo(this)`の`this`が指しているのが`SampleObserver`自身であることを見落とし、「`_target`を渡すべきでは」と混同しがちです。1-1レッスンの`AddTo(_target)`との違いを見比べておきましょう。

## 理解度チェック
1. `SampleObserver`が`SampleSubject`のデータを受け取るために呼んでいるメソッドは何でしたか。
2. `[SerializeField] private SampleSubject _target;`は、どのような役割を果たしていますか。
3. `SampleObserver`側の`.AddTo(this)`と、1-1レッスンの`.AddTo(_target)`とでは、それぞれ「何が破棄されたら購読を解除するか」がどう違いますか。
