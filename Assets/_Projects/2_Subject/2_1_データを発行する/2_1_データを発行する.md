# 2-1. データを発行する

## この回で学ぶこと
- `Subject<T>`型のプロパティを自分のクラスに定義する方法を知る
- `OnNext`メソッドを呼び出すことで、Subjectからデータを発行できることを理解する
- Observer（購読者）がいない状態でデータを発行しても、見た目には何も起こらないことを体験する

## 前提知識
- 「2-0. Subjectとは」で学んだ、Subjectが持つ「データを発行できる」「データを監視できる」という2つの役割
- ジェネリクス（`List<int>`のような`<T>`を使った書き方）の基本的な見た目
- `private void Update()`のような、Unityのイベント関数

## 概念解説
前回、Subjectは「Observableでもあり、Observerでもある」特別な存在だと学びました。今回は、その**Observableとしての役割、つまりデータを発行する**部分を実際に使ってみます。

Subjectでデータを発行するには、**`OnNext`メソッド**を呼び出します。`OnNext`は「次のデータはこれです」とSubjectに伝えるための命令で、これを呼ぶことで、このSubjectを監視している（Subscribeしている）Observerに対してデータが通知されます。

ここで大事なポイントがあります。**「発行する」ことと「誰かがそれを受け取る」ことは別物**です。ラジオ局が電波を発信していても、受信機の電源が入っていなければ誰にも聞こえないのと同じで、`OnNext`を呼んでも、そのSubjectを購読しているObserverが1人もいなければ、何も起こったように見えません。今回のレッスンではまだObserver側のコードを書かないため、実際にPlayしてもConsoleには何も表示されません。これは失敗ではなく、意図された挙動です。次回、Observer側を実装することで初めて「発行したデータを受け取る」という体験ができます。

## シーンの操作方法
1. Playボタンを押してシーンを実行します。
2. `Scripts`オブジェクトにアタッチされた`SampleSubject`が毎フレーム`OnNext`を呼び出していますが、**Consoleには何も表示されません**。
3. Hierarchyの`Scripts`オブジェクトを選択し、Inspector上で`SampleSubject`コンポーネントが動作していることを確認してください（ただし出力が無いため、動いているかどうかは見た目からは分かりません）。この「何も起きない」という状態自体が、このレッスンで体験してほしいポイントです。

## コード解説
```csharp
public class SampleSubject : MonoBehaviour
{
    // 他クラスから参照するためのプロパティ
    public Subject<int> UpdateSubject { get; } = new();

    private int _count;

    private void Start()
    {
        // このコンポーネントが破棄されたらイベントの発行を終了
        // この処理を書かないとオブジェクトが破棄された後も処理が動き続ける→メモリーリークの原因になる
        UpdateSubject.AddTo(this);
    }

    private void Update()
    {
        // イベントを発行
        // 第一引数は購読者に送るデータ（特になければUnit.Default）を指定する
        UpdateSubject.OnNext(_count++);
    }
}
```
- `public Subject<int> UpdateSubject { get; } = new();`：`int`型のデータを発行するSubjectを、読み取り専用のプロパティとして公開しています。こう書くことで、他のクラスから`sampleSubject.UpdateSubject`という形でこのSubjectを参照できるようになります。
- `UpdateSubject.AddTo(this);`：SubjectそのものにもAddToが使えます。これを書いておくことで、このコンポーネント（`SampleSubject`）が破棄されたときにSubjectも合わせて破棄され、それ以降の発行や購読を止めることができます。コメントにもある通り、これを書き忘れるとメモリリークの原因になるため、Subjectを定義したら必ずセットで書く習慣をつけましょう。
- `UpdateSubject.OnNext(_count++);`：`_count`の値を発行してから1つ増やしています。`Update`は毎フレーム呼ばれるので、このSubjectは毎フレーム連番の`int`値を発行し続けることになります。

## 実行結果の例
このレッスンの時点ではConsoleに何も表示されません。Playしても真っ黒なままのConsoleを見て、「あれ、動いていないのかな？」と感じるかもしれませんが、それが正しい状態です。次回、Observerを追加した瞬間に`frame: 0`, `frame: 1`, `frame: 2`...という連番のログが流れ始めます。

## よくあるつまずきポイント
- 「Consoleに何も出ないから、コードが間違っている」と思い込んでしまいがちですが、これは正常な動作です。Observer（Subscribeする側）がまだ存在しないため、発行されたデータを受け取る人がいない、というだけです。
- `Subject<int>`のようにジェネリクスで型を指定する部分を見落として、「Subjectには何でも入るのでは」と誤解しないようにしましょう。`Subject<int>`は`int`型のデータしか流せません。
- `UpdateSubject.AddTo(this);`を書き忘れると、動作は一見変わらないように見えますが、オブジェクト破棄後もSubjectが生き続けてしまいます。「見た目に変化がないから省略してよい」わけではない点に注意してください。

## 理解度チェック
1. Subjectでデータを発行するために呼び出すメソッドは何でしたか。
2. このレッスンでPlayしてもConsoleに何も表示されないのはなぜですか。
3. `UpdateSubject.AddTo(this);`を書く目的を説明してください。
