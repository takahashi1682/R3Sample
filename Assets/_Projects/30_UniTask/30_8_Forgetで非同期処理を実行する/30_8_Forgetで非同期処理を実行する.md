# 30-8. Forgetで非同期処理を実行する

## この回で学ぶこと
- `.Forget()`の意味と、「投げっぱなし（fire-and-forget）」の非同期処理の書き方
- 複数の非同期処理を、終わりを待たずに同時並行で走らせる方法
- 【重要】`.Forget()`を使う場合でも、`CancellationToken`は必ず渡すべきという安全な書き方

## 前提知識
- 30-3〜30-6で学んだ`async`/`await`、`CancellationToken`の基本
- `async`を付けたメソッドは`UniTask`（や`UniTask<T>`）を返せる、という基本知識

## 概念解説
これまでのサンプルは、すべて非同期処理が終わるまで`await`で律儀に待っていました。しかし実際のゲームでは、「複数の処理を同時に走らせて、それぞれの完了は待たずに次の処理に進みたい」という場面がよくあります。

`async`を付けたメソッドを呼び出しても`await`しない場合、C#のコンパイラは「戻り値（`UniTask`）を無視していますが、本当に大丈夫ですか？」という警告を出します。この警告に対して「はい、意図的に無視して構いません」と明示するのが`.Forget()`です。`.Forget()`を呼ぶことで、「この処理は投げっぱなしにします、終わるのを待つつもりはありません」という意思表示になります。

ここで絶対に誤解してほしくないのが、「Forget＝何が起きても放置していい」ではないという点です。`CancellationToken`を渡さずに`.Forget()`すると、対象のオブジェクトが破棄された後もその非同期処理は生き続け、すでに破棄されたはずのオブジェクトへの参照をいつまでも持ち続けてしまいます。これは典型的なメモリリークの原因です。「Forget」は英語で「忘れる」という意味ですが、だからといって処理の後始末まで忘れてよいわけではありません。

このレッスンのサンプルコードは、きちんと`destroyCancellationToken`を`.Forget()`する処理に渡しています。これは「終わりを待たずに投げっぱなしにする場合でも、オブジェクトが破棄されたらちゃんと連動してキャンセルされる」ようにした、安全な書き方の見本です。今後自分で`.Forget()`を使うときは、必ずこのサンプルのように`CancellationToken`とセットで使う習慣をつけてください。

## シーンの操作方法
1. Playボタンを押します。
2. Consoleを開いた状態で、ログが出力される順番とタイミングを観察してください。
3. 「この時点で0秒かかる」というログがほぼ即座に表示され、その後1秒後・3秒後・5秒後に、それぞれ対応するログが順番に表示されることを確認してください。

## コード解説
```csharp
// awaitしない場合は、async不要
private void Start()
{
    // キャンセルトークンを生成する
    var token = destroyCancellationToken;

    // 一定時間後にログを出力する非同期処理を実行する
    DelayLog(5, "5秒間の処理", token).Forget(); // 待たずに次へ
    DelayLog(3, "3秒間の処理", token).Forget(); // 待たずに次へ
    DelayLog(1, "1秒間の処理", token).Forget(); // 待たずに次へ

    Debug.Log("この時点で0秒かかる");
}

private async UniTask DelayLog(float second, string message, CancellationToken token)
{
    await UniTask.Delay(TimeSpan.FromSeconds(second), cancellationToken: token);
    Debug.Log(message);
}
```
- `private void Start()`: `Start`自体は`await`していないので`async`を付ける必要がありません。
- `DelayLog(5, "5秒間の処理", token).Forget();`: `DelayLog`は`UniTask`を返す非同期メソッドですが、その戻り値を`await`せずに`.Forget()`することで、終わりを待たずにすぐ次の行へ進みます。この3行はいずれも「呼び出した瞬間に開始され、あとは裏側で並行して進む」処理になるため、3つの`DelayLog`はほぼ同時にスタートします。
- `token`（＝`destroyCancellationToken`）を3つとも`DelayLog`に渡していることに注目してください。これにより、もしこのオブジェクトが5秒経過する前に破棄されたとしても、投げっぱなしにした3つの処理はすべて正しくキャンセルされます。
- `Debug.Log("この時点で0秒かかる");`: `DelayLog`をどれも`await`していないため、この行は3つの非同期処理の完了を待たずに即座に実行されます。

## 実行結果の例
Consoleには次の順番でログが表示されます。
1. （ほぼ即座）「この時点で0秒かかる」
2. （約1秒後）「1秒間の処理」
3. （約3秒後）「3秒間の処理」
4. （約5秒後）「5秒間の処理」

## よくあるつまずきポイント
- `DelayLog(5, ...)`、`DelayLog(3, ...)`、`DelayLog(1, ...)`の順に書かれているため、「この順番で処理される（5秒→3秒→1秒の順）」と誤解しがちですが、実際には3つとも同時にスタートし、それぞれの待機時間が短いものから先に完了します。
- `.Forget()`を使えば`CancellationToken`を渡さなくても問題ないと考えてしまう学生が多いですが、それは「後片付けをしなくていい」という意味ではありません。渡し忘れると、オブジェクトが破棄された後も処理が残り続けるリスクがあります。
- `await`していないのに`async`を付けてしまう、または`await`しているのに`async`を付け忘れてコンパイルエラーになる、といった`async`/`await`の対応関係の混乱。
