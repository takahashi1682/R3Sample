# 30-7. バックグラウンドで別シーンをロードする

## この回で学ぶこと
- `SceneManager.LoadSceneAsync`とUniTaskを組み合わせて、シーンを非同期に読み込む方法
- `allowSceneActivation`を使って、読み込み完了後の「実際の切り替わりタイミング」を自分で制御する方法
- `AsyncOperation.progress`が0.9までしか進まないというUnity特有の仕様と、その対処法

## 前提知識
- Unity基礎コースで習ったシーン遷移の基本（`SceneManager.LoadScene`など）
- 30-6で学んだ`UniTask.WaitUntil`（条件が満たされるまで待つ）
- ボタンのクリックイベント（`Button.onClick`）の基本的な使い方

## 概念解説
ロード画面でよくあるのが、「裏側では読み込みが進んでいるけれど、実際に画面が切り替わるのはプレイヤーがボタンを押した時にしたい」というパターンです。これを実現するのが`SceneManager.LoadSceneAsync`と`allowSceneActivation`の組み合わせです。

`SceneManager.LoadSceneAsync`はシーンの読み込みを裏側（バックグラウンド）で開始し、その進行状況を持った`AsyncOperation`というオブジェクトを返します。ここで`allowSceneActivation`を`false`にしておくと、読み込みが終わってもUnityは自動的にシーンを切り替えません。遊園地でたとえるなら、次のアトラクションの準備を裏側でこっそり進めておき、「入場ゲートを開けるタイミング」だけは係員が手動で決める、というイメージです。

もう1つ押さえておきたいのが、`AsyncOperation.progress`は0.9までしか進まないというUnityの仕様です。これは、シーンの読み込み自体は0.9あたりでほぼ完了しており、残りの0.9〜1.0の区間は「実際にシーンを有効化する」という最後の仕上げ処理に使われるためです。そのためサンプルコードでは、`progress`が0.9未満の間だけプログレスバーに反映し、`UniTask.Yield()`で1フレームずつ待ちながら進行状況を監視するループを書いています。`UniTask.Yield()`はコルーチンの`yield return null`に相当する「1フレームだけ待つ」処理です。

## シーンの操作方法
1. Playボタンを押します。
2. 「ロードする」ボタンを押すと、裏側で次のシーンの読み込みが始まり、プログレスバーが少しずつ進みます。
3. プログレスバーが0.9あたりまで進んで一瞬止まったように見えますが、これは仕様通りの挙動です。読み込みが完了すると、プログレスバーが1.0まで進み、それまで押せなかった「遷移する」ボタンが押せるようになります。
4. 「遷移する」ボタンを押すと、実際にシーンが切り替わり、「NextScene」という文字だけが表示されるシンプルな次のシーンに移動することを確認してください。

## コード解説
```csharp
private async void Start()
{
    // ボタンが押されるまで待機する
    await UniTask.WaitUntil(() => _isLoadStart);

    // シーンを非同期でロードする
    await LoadSceneAsync(_nextSceneName);

    // 完了時に呼ばれる処理
    _loadButton.interactable = false;
    _transitionButton.interactable = true;
}
```
- `await UniTask.WaitUntil(() => _isLoadStart);`: 30-6で学んだ`WaitUntil`を使い、「ロードする」ボタンが押されるまで待っています。
- `await LoadSceneAsync(_nextSceneName);`: 実際のシーン読み込み処理（下記）が終わるまで待っています。

```csharp
private async UniTask LoadSceneAsync(string sceneName)
{
    _operation = SceneManager.LoadSceneAsync(sceneName);
    _operation.allowSceneActivation = false;

    while (_operation.progress < 0.9f)
    {
        _progressSlider.value = _operation.progress;
        await UniTask.Yield();
    }

    _progressSlider.value = 1.0f;
}
```
- `_operation.allowSceneActivation = false;`: 読み込みが終わっても自動でシーンを切り替えないようにしています。
- `while (_operation.progress < 0.9f)`: 進捗が0.9未満の間だけループし、プログレスバーの値を更新しつつ`UniTask.Yield()`で1フレーム待つ、を繰り返しています。
- `_transitionButton.onClick.AddListener(() => { _operation.allowSceneActivation = true; });`（`Awake`内）: 「遷移する」ボタンが押されたタイミングで`allowSceneActivation`を`true`にし、初めて実際のシーン切り替えを許可しています。

このコードでは`CancellationToken`を渡していません。このシーンは、ボタン操作からシーン遷移までが一直線に完結するシンプルな流れであり、途中でこのオブジェクトが破棄される想定をしていないためです。ただし、より複雑な画面遷移を作る場合は、ここまでの回で学んだ`destroyCancellationToken`などを組み合わせることも検討してください。

## 実行結果の例
「ロードする」ボタンを押すと、プログレスバーが0から0.9付近までじわじわと進み、その後すぐに1.0になります。「遷移する」ボタンが有効化され、押すと画面が切り替わり「NextScene」という文字が表示されます。

## よくあるつまずきポイント
- プログレスバーが0.9で止まって見えることを「バグ」「読み込みが終わらない」と勘違いしてしまう。これはUnityの仕様であり、正しい実装です。
- `allowSceneActivation`を`true`にするタイミングを忘れてしまい、「読み込みは終わっているはずなのに、いつまで経ってもシーンが切り替わらない」という状態になる。
- `WaitUntil(() => _isLoadStart)`で待っているのはあくまで「ロード開始ボタンが押されたかどうか」であり、実際のシーン読み込みやシーン切り替えのタイミング制御は、その後の`LoadSceneAsync`内で別に行われている、という処理の流れを整理できていない。

## 理解度チェック
