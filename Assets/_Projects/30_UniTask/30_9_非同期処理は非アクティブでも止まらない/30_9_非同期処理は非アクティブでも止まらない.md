# 30-9. 非同期処理は非アクティブでも止まらない

## この回で学ぶこと
- `SetActive(false)`でGameObjectを非アクティブにしても、実行中のUniTaskの非同期処理は止まらないという事実
- 「非アクティブ」と「破棄（Destroy）」がまったく別のライフサイクルイベントであるという区別
- `destroyCancellationToken`が非アクティブ化には反応しない理由

## 前提知識
- 30-4・30-5で学んだ`destroyCancellationToken`（破棄と連動するキャンセル）
- 30-8で学んだ`.Forget()`（投げっぱなしの非同期処理）
- Unity基礎コースで習った`SetActive`とMonoBehaviourの`Update`などのライフサイクル

## 概念解説
MonoBehaviourの`Update`のようなメッセージ関数は、GameObjectが非アクティブ（`SetActive(false)`）になると呼ばれなくなります。この経験から、多くの学生が「非アクティブになったら、そのオブジェクト上で動いていた処理はすべて止まるはずだ」と考えてしまいます。しかし、UniTaskの非同期処理についてはこれが当てはまりません。

UniTaskの非同期処理は、Unityの`Update`のようなメッセージループの仕組みに乗っているのではなく、`PlayerLoop`という、より内部的な仕組みに直接処理を差し込んで動作しています（30-2で学んだ内容を思い出してください）。そのため、GameObjectの非アクティブ状態には影響されず、実行され続けます。実行元のスクリプトが非アクティブになっても、すでに始まっている非同期処理はそのまま動き続けるのです。

たとえるなら、お店が「本日臨時休業」の札を出している（＝非アクティブ）だけの状態です。お客さんの対応（`Update`など）は止まっていても、裏の厨房ではタイマー（非同期処理）が律儀に動き続けています。お店を取り壊してしまう（＝Destroy）まで、そのタイマーは生き続けます。

ここが重要なポイントです。「非アクティブ」と「破棄」はまったく別のライフサイクルイベントです。`destroyCancellationToken`はオブジェクトが破棄された時にしか反応せず、`SetActive(false)`にしても何も起こりません。もし非アクティブになったタイミングで非同期処理も止めたい場合は、30-5で学んだ`CancellationTokenSource`を自分で用意し、非アクティブになるタイミングで明示的に`Cancel()`を呼ぶ、といった実装を自分で追加する必要があります。

## シーンの操作方法
1. Playボタンを押します。
2. 画面上のキャラクターをクリックしてください。クリックした瞬間、キャラクターが非表示（非アクティブ）になります。
3. そのまま何もせずに約1秒待つと、キャラクターが自動的に再び表示されることを確認してください。この間、Consoleにエラーは出ません（オブジェクトはDestroyされていないためです）。

## コード解説
```csharp
public void OnPointerClick(PointerEventData eventData)
{
    // 自身を非表示にする
    gameObject.SetActive(false);

    // 一定時間後に自身をアクティブにする
    ReactivateAfterDelay(destroyCancellationToken).Forget();
}

private async UniTask ReactivateAfterDelay(CancellationToken token)
{
    // 1秒待機する
    await UniTask.Delay(1000, cancellationToken: token);
    gameObject.SetActive(true);
}
```
- `gameObject.SetActive(false);`: クリックされた瞬間、このオブジェクト自身を非アクティブにしています。
- `ReactivateAfterDelay(destroyCancellationToken).Forget();`: 30-8で学んだ`.Forget()`を使い、「1秒後に再アクティブにする」処理を投げっぱなしで開始しています。`gameObject`自体は非アクティブになっただけで破棄されたわけではないため、`destroyCancellationToken`はまだキャンセルされておらず、この非同期処理は問題なく動き続けます。
- `await UniTask.Delay(1000, cancellationToken: token);`: ここでの`token`は`destroyCancellationToken`です。もしこのGameObjectが（非アクティブ化ではなく）本当にDestroyされていた場合は、ここで`OperationCanceledException`が発生し、次の行は実行されません。
- `gameObject.SetActive(true);`: 非アクティブになっていたオブジェクトを、コードから再びアクティブに戻しています。オブジェクト自身が非アクティブなままでも、その中で動いているスクリプトのコードは実行され続けるため、この行は問題なく動作します。

## 実行結果の例
キャラクターをクリックすると、その場で画像がすぐに消えます。特にログは出ません。その約1秒後、何も操作していないにもかかわらず、キャラクターが自動的に再表示されます。

## よくあるつまずきポイント
- 「非アクティブ＝処理停止」という思い込みが根強く、「クリックしたら非表示になったのだから、その後の1秒待ちの処理もどこかで止まっているはずだ」と誤解してしまう。実際には、非アクティブになっても非同期処理はそのまま動き続けます。
- `destroyCancellationToken`という名前から、「非アクティブになった時にもキャンセルされる」と勘違いしてしまう。この名前が示す通り、反応するのはあくまで“Destroy”（破棄）のタイミングだけです。
- 非アクティブ化したタイミングで処理も止めたい場合、`destroyCancellationToken`をそのまま使っても実現できません。30-5で学んだ`CancellationTokenSource`を使い、`OnDisable`などのタイミングで明示的に`Cancel()`を呼ぶ設計が必要になることに気づけるかどうかがポイントです。

## 理解度チェック
1. `SetActive(false)`にしても非同期処理が止まらないのはなぜですか。30-2で学んだUniTaskの仕組みと結びつけて説明してください。
2. 「非アクティブ」と「破棄」の違いを、`destroyCancellationToken`の反応の違いをふまえて説明してください。
3. もし「キャラクターが非アクティブになったら、再アクティブ化の処理もキャンセルしたい」という仕様に変更するとしたら、このコードをどのように書き換える必要がありますか。
