# 30-3. asyncとawaitとDelay

## この回で学ぶこと
- `async`と`await`の基本的な書き方
- `UniTask.Delay`で時間待ちの処理を書く方法
- 【重要】非同期処理は、何もしなければオブジェクトの破棄とは連動していないという事実

## 前提知識
- 30-0〜30-2で学んだUniTaskの概要（メインスレッド上で動作すること）
- C#のメソッド宣言（戻り値の型、修飾子）の基本

## 概念解説
UniTaskの文法として`await`を使う場合は、必ずメソッド宣言時に`async`を付ける必要があります。`async`は「このメソッドの中では`await`を使いますよ」という宣言のようなものだとイメージしてください。

`await`は「ここで一旦処理を止めて、非同期処理が完了したら続きを実行する」という意味を持つキーワードです。ただし「止める」といっても、メインスレッドをフリーズさせているわけではありません。`await`に到達すると、そのメソッドの続きは一旦保留され、対象の処理（今回であれば3秒待つ処理）が完了したタイミングで、続きの処理が再開されます。その間メインスレッドは他の仕事（描画や入力処理）を続けられます。

このレッスンのサンプルは、`Start`メソッドの途中で3秒待機するだけのシンプルなプログラムです。

ここで非常に重要な注意点があります。このプログラムは、非同期処理がオブジェクトの破棄と紐付けられていません。つまり、3秒経過する前に「Scripts」オブジェクトを削除しても、`UniTask.Delay`の処理は止まりません。目覚まし時計を3秒後にセットして家を出た（＝オブジェクトを壊した）としても、目覚まし時計自体は誰もいなくても律儀に鳴り続けるようなものだとイメージしてください。「オブジェクトが無くなったら、そこで動いていた処理も自動的に止まるはずだ」という思い込みは、この時点ではまだ間違いです。この問題をどう解決するかが、次の30-4で学ぶ`CancellationToken`のテーマになります。

## シーンの操作方法
1. Playボタンを押します。
2. 何も操作せずに3秒待ち、Consoleに「3秒経過しました」というログが出ることを確認します。
3. もう一度Playし直し、今度は3秒が経過する前にHierarchy上で「Scripts」オブジェクト（`MyTask`がアタッチされているオブジェクト）を選択し、削除（Delete）します。
4. オブジェクトを削除したにもかかわらず、3秒後にきちんと「3秒経過しました」がConsoleに出力されることを確認してください。これがこのレッスンで体験してほしい現象です。

## コード解説
```csharp
private async void Start()
{
    // await で非同期処理が完了するまで待機する
    await UniTask.Delay(TimeSpan.FromSeconds(3)); // 3秒待機する

    Debug.Log("3秒経過しました");
}
```
- `private async void Start()`: `Start`メソッドの中で`await`を使うために`async`を付けています。
- `await UniTask.Delay(TimeSpan.FromSeconds(3));`: 3秒間待機する非同期処理です。ここではキャンセルの仕組み（`CancellationToken`）を一切渡していません。そのため、この待機処理はどのオブジェクトの生死ともまったく連動していない、「宙に浮いた」処理になっています。
- `Debug.Log("3秒経過しました");`: 3秒経過後、`await`の続きとして実行されます。

## 実行結果の例
- 通常時: Playしてから3秒後、Consoleに「3秒経過しました」と表示されます。
- 「Scripts」オブジェクトを3秒以内に削除した場合: オブジェクトがHierarchyから消えても、3秒後に変わらず「3秒経過しました」がConsoleに表示されます。エラーは出ません。

## よくあるつまずきポイント
- 「オブジェクトを消せば、そこで動いていた処理も止まるはずだ」という思い込みを持ったまま先に進んでしまう。実際には、明示的に紐付けない限り非同期処理は止まりません。この体験こそが次回のCancellationTokenの必要性につながるので、必ず自分の手でオブジェクト削除を試してみてください。
- `async void`と書いているため、この`Start`メソッドの完了を外部から`await`することができません（戻り値がないため）。`async void`は基本的にイベントハンドラ的な入り口（`Start`など）だけで使い、それ以外では`async UniTask`を使うのが基本です。

## 理解度チェック
1. `async`キーワードと`await`キーワードは、それぞれどういう役割を持っていますか。
2. 「Scripts」オブジェクトを3秒以内に削除しても、なぜ「3秒経過しました」というログが出力されるのですか。
3. `await`は「メインスレッドを止めて待つ」ことと同じ意味ですか。30-2の内容を踏まえて説明してください。
