# 10_5. CombineLatest

## この回で学ぶこと
- `Observable.CombineLatest`が「各ストリームの最新値の組み合わせ」を流すオペレーターであることを理解する
- CombineLatestが値を流すタイミング（全ストリームが1回以上値を出した後、いずれかが値を出すたび）を理解する
- CombineLatestとZip/ZipLatestの根本的な違い（値を消費するか、し続けるか）を理解する

## 前提知識
- Observable / Subject / Subscribe の基本（0〜4の回）
- `OnNext` / `OnCompleted`を手動で呼び出してストリームの流れを確認する方法
- `AddTo(this)`によるリソース管理
- 10_3_Zip、10_4_ZipLatestの内容（Zip系との比較で理解が深まります）

## 概念解説
CombineLatestは、「複数のストリームの、それぞれの最新値を常に組み合わせて流す」オペレーターです。

イメージとしては、複数のステータス表示ランプが並んだ操作パネルです。パネルには「体力ランプ」と「MPランプ」があり、どちらか一方の値が変化するたびに、パネル全体（体力とMPの組み合わせ）が再表示されます。ただし、まだ一度も点灯していないランプがある間は、パネル全体の表示はまだ出せません。

```
subject1: --1-----------------→(最新値:1)
subject2: -----2----3---------→(最新値:2→3)
Combine : -----(1,2)-(1,3)----→
```

- 全てのストリームに最低1回ずつ値が流れるまでは、何も出力されません
- 全てのストリームに1回ずつ値が揃った後は、**いずれかのストリームに新しい値が流れるたびに**、その時点の「各ストリームの最新値」を組み合わせて出力します
- Zip/ZipLatestと違い、一度使った値がキューから消費されることはありません。同じ値が何度も再利用されます

ZipやZipLatestとの違いを整理すると、Zip系は「両方に新しい値が1個ずつ揃う」までじっと待ってペアを作りますが、CombineLatestは「片方だけが新しい値を出しても、もう片方の最新値と組み合わせてすぐ流す」という点が大きく異なります。Zip系は値を1回ずつ消費していくのに対し、CombineLatestは値を「保持し続けて使い回す」イメージです。

## シーンの操作方法
1. `10_5_CombineLatest`シーンを開いてPlayします。
2. Consoleを確認し、`_subject1.OnNext(1)`の直後は何も出力されないことを確認してください（`_subject2`がまだ一度も値を出していないため）。
3. `_subject2.OnNext(2)`の直後に`next.1`→`next.3`ではなく`next.1`→`next.2`→区切り線が出力されることを確認してください。
4. 続けて`_subject2.OnNext(3)`を呼んだ直後、`_subject1`には新しい値を流していないにもかかわらず`next.1`→`next.3`→区切り線が出力されることに注目してください（`_subject1`の最新値`1`が再利用されています）。
5. 両方が`OnCompleted()`された後、`completed.`が出力されることを確認してください。

## コード解説
```csharp
Observable
    .CombineLatest(
        _subject1,
        _subject2
    ).Subscribe(
        onNext: x =>
        {
            foreach (var item in x)
            {
                Debug.Log("next." + item);
            }
            Debug.Log("------------------------");
        },
        ...
```
Zip系と同じく、流れてくる値`x`は各ストリームの値をまとめた配列（組）です。コードの見た目はZip/ZipLatestとほぼ同じですが、中身の動きは大きく異なります。

```csharp
_subject1.OnNext(1); // 流れない
_subject2.OnNext(2); // next: 1.  >  next: 2.
```
`_subject1`に`1`が流れた時点では、`_subject2`がまだ一度も値を出していないため、組み合わせが作れず何も出力されません。`_subject2`に`2`が流れた瞬間、両方に最新値が揃うので`(1, 2)`が流れます。

```csharp
_subject2.OnNext(3); // next: 1.  >  next: 3.
```
ここがCombineLatestの理解の要になる部分です。`_subject1`には新しい値を流していませんが、`_subject2`に新しい値`3`が流れたことで、CombineLatestは`_subject1`の**保持している最新値`1`**と`_subject2`の新しい値`3`を組み合わせて、`(1, 3)`を流します。Zipのように「値を使い切って消費する」のではなく、「最新値を保持しておいて何度でも使い回す」動きになっている点に注目してください。

```csharp
_subject1.OnCompleted();
_subject2.OnCompleted(); // completed.
```
Merge同様、全ての合成元ストリームが完了した時点でCombineLatest全体も完了します。

## 実行結果の例
```
next.1
next.2
------------------------
next.1
next.3
------------------------
completed.
```

## よくあるつまずきポイント
- 「両方に新しい値が来ないと出力されない」というZipの感覚のまま使うと、CombineLatestの「片方だけの変化でも出力される」動きに戸惑います。値が使い切りではなく保持・使い回しである点を意識しましょう。
- 最初の`_subject1.OnNext(1)`が無視されたように見えますが、これは失われたわけではなく「`_subject2`の値が来るまで保持されている」だけです。ペアが作れないうちは出力されないだけで、値自体はちゃんと覚えられています。
- 完了の条件はMergeと同じく「**全ての**合成元が完了すること」です。Concatのように順番に完了を待つわけではありません。

## 理解度チェック
1. `_subject1`に`1`のみを流し、`_subject2`には一度も値を流さなかった場合、Subscribeのログには何が出力されますか。
2. `_subject2.OnNext(3)`のときに出力されるペアが`(1, 3)`になる理由を、Zipとの違いを踏まえて説明してください。
3. 「フォームの名前欄とメール欄の両方が入力されたら送信ボタンを有効化したい。どちらかが変更されるたびに再チェックしたい」という要件には、Zip・CombineLatestのどちらが適していますか。理由も答えてください。
