# 10_4. ZipLatest

## この回で学ぶこと
- `Observable.ZipLatest`がZipと同じく「両方に値が揃ったらペアにする」オペレーターであることを理解する
- ZipとZipLatestの唯一にして最大の違い（キューの先頭を使うか、最新の値を使うか）を理解する
- 名前が似ているZipとZipLatestを、コードの実行結果の違いから区別できるようになる

## 前提知識
- Observable / Subject / Subscribe の基本（0〜4の回）
- `OnNext` / `OnCompleted`を手動で呼び出してストリームの流れを確認する方法
- `AddTo(this)`によるリソース管理
- **10_3_Zipの内容（このレッスンはZipとの比較が中心になるため必須）**

## 概念解説
ZipLatestは、名前の通りZipの仲間です。「全てのストリームに値が1個以上揃ったときにペアにして流す」という基本動作はZipとまったく同じです。

違うのはただ1点、**片方のストリームに値が複数回連続で流れてキューに溜まった場合、ペアにする値としてどれを選ぶか**です。

- **Zip**：キューに溜まった値のうち、**先に来た値（古い方）**を使う
- **ZipLatest**：キューに溜まった値のうち、**最後に来た値（最新の方）**を使い、それより古い値は捨てられる

先ほどの工場の例えで言うと、Zipは「先入れ先出し」で律儀に部品を1個ずつ使いますが、ZipLatestは「一番新しく届いた部品を使い、それより古い部品は倉庫の奥にあっても無視して最新のものだけを使う」というイメージです。

```
subject1: --1--------5------->
subject2: -----2--3--4-------->

Zip       : -----(1,2)-----(5,3)->   ← 古い方(3)を使う
ZipLatest : -----(1,2)-----(5,4)->   ← 新しい方(4)を使う
```

このように、コード上の見た目はZipとほぼ同じ（`Zip`を`ZipLatest`に置き換えるだけ）でも、片方のストリームだけが先に複数回値を出すケースでは結果が変わります。両方のストリームが常にきっちり1対1のペースで値を出す場合は、ZipとZipLatestの結果は同じになります。

## シーンの操作方法
1. `10_4_ZipLatest`シーンを開いてPlayします。
2. Consoleを確認し、`next.1`→`next.2`→区切り線が出た後、しばらく何も出ないタイミングがあることを確認してください。
3. `_subject1.OnNext(5)`が呼ばれた瞬間に`next.5`→`next.4`→区切り線が出力されることを確認してください。前回のZipのレッスンでは同じ場面で`3`が出力されていたことと比較しましょう。
4. 両方が`OnCompleted()`された後、`completed.`が出力されることを確認してください。

## コード解説
```csharp
Observable
    .ZipLatest(
        _subject1,
        _subject2
    ).Subscribe(
        onNext: x =>
        {
            foreach (var item in x)
            {
                Debug.Log("next." + item);
            }
            Debug.Log("------------------------");
        },
        ...
```
`Zip`が`ZipLatest`に変わっている以外、コードの構造は10_3_Zipとまったく同じです。

```csharp
_subject1.OnNext(1); // 流れない
_subject2.OnNext(2); // next: 1.  >  next: 2.
```
ここまではZipと同じ動きです。それぞれのストリームに初めて値が来た時点でペアが1組できるので、`(1, 2)`が流れます。

```csharp
_subject2.OnNext(3); // 流れない
_subject2.OnNext(4); // 流れない
_subject1.OnNext(5); // next: 5.  >  next: 4.
```
ここがZipとの違いが出るポイントです。`_subject2`に`3`、続けて`4`が流れ、どちらも`_subject1`側の値がまだないため出力されずに待機します。`_subject1`に`5`が流れた瞬間、ペアになる相手として選ばれるのは**キューの中で最も新しい`4`**です。Zipのレッスンでは同じ状況で`3`が選ばれていたことを思い出してください。`3`はこの時点で使われずに捨てられます。

```csharp
_subject1.OnCompleted();
_subject2.OnCompleted(); // completed.
```
Zipと同様、`_subject1`が完了してこれ以上ペアを作れなくなった時点で、ZipLatest全体も完了します。

## 実行結果の例
```
next.1
next.2
------------------------
next.5
next.4
------------------------
completed.
```

## よくあるつまずきポイント
- Zipとの違いは「どの値を使うか」だけで、「いつ値を流すか」（＝両方に値が揃ったタイミング）は同じです。混同して「ZipLatestは片方に値が来るたびに毎回流れる」と思わないよう注意してください（それはCombineLatestの動きです）。
- 名前が似ているため、コードを書くときに`Zip`と`ZipLatest`を打ち間違えないようにしましょう。実行結果が変わってもエラーにはならないため、気づきにくいバグの原因になります。
- 「捨てられた値（このコードでは`3`）はどこにも出てこない」という点を見落とさないようにしましょう。

## 理解度チェック
1. ZipとZipLatestの違いを一言で説明してください。
2. コード中で`3`という値は最終的にどうなりましたか。理由も含めて説明してください。
3. もし`_subject1`と`_subject2`が常に交互にきっちり1回ずつ値を流す場合、ZipとZipLatestの実行結果に違いは出るでしょうか。理由も考えてみましょう。
