# 10_3. Zip

## この回で学ぶこと
- `Observable.Zip`が複数のストリームの値を「同じ順番同士」でペアにする仕組みを理解する
- Zipが値を流すタイミング（全てのストリームに値が揃ったとき）を理解する
- 片方のストリームに複数回値が流れた場合、Zipは古い方（先に流れた値）から順にペアにすることを理解する

## 前提知識
- Observable / Subject / Subscribe の基本（0〜4の回）
- `OnNext` / `OnCompleted`を手動で呼び出してストリームの流れを確認する方法
- `AddTo(this)`によるリソース管理
- 10_1_Merge、10_2_Concatの内容（合成の基本的な考え方）

## 概念解説
Zipは、複数のストリームから届いた値を「同じ順番同士」でペアにして流すオペレーターです。

イメージとしては、工場の組み立てラインです。ベルトコンベアA（ストリーム1）とベルトコンベアB（ストリーム2）から部品が流れてきて、両方から1個ずつ部品が揃ったタイミングで、初めて1セットの製品として次の工程に流れます。片方のコンベアだけに部品がいくつ流れてきても、もう片方が来るまでは製品は完成しません。

```
subject1: --1--------5------->
subject2: -----2--3--4-------->
Zip     : -----(1,2)-----(5,3)->
```

- 各ストリームは内部でそれぞれ「まだペアになっていない値」をキュー（待ち行列）として溜めておきます
- 全てのストリームに1個以上値が溜まった時点で、それぞれの**先頭（＝先に流れてきた値）**を1個ずつ取り出してペアにし、合成後のストリームに流します
- 片方のストリームだけに何度も値が流れても、もう片方に値が来るまでは何も流れません

他の合成オペレーターとの違いとして、Zipは「値の中身」ではなく「値が来た順番（インデックス）」でペアを作る点が重要です。次に学ぶZipLatestは似た名前ですが、ペアにする際に「先に流れた値」ではなく「最新の値」を使う点が異なります。またCombineLatestは、いずれかのストリームに値が流れるたびに毎回組み合わせを再計算しますが、Zipは両方が新しく1個ずつ揃わないと流れません。

## シーンの操作方法
1. `10_3_Zip`シーンを開いてPlayします。
2. Consoleを上から順に確認し、`next.1`→`next.2`→区切り線が出た後、しばらく何も出ないタイミングがあることを確認してください（`_subject2`に2回値を流しても何も起きません）。
3. `_subject1.OnNext(5)`が呼ばれた瞬間に`next.5`→`next.3`→区切り線が出力されることを確認してください（`4`ではなく`3`とペアになる点に注目）。
4. 両方が`OnCompleted()`された後、`completed.`が出力されることを確認してください。

## コード解説
```csharp
Observable
    .Zip(
        _subject1,
        _subject2
    ).Subscribe(
        onNext: x =>
        {
            foreach (var item in x)
            {
                Debug.Log("next." + item);
            }
            Debug.Log("------------------------");
        },
        ...
```
Zipから流れてくる値`x`は、各ストリームの値をまとめた配列（または組）になります。`foreach`で中身を1つずつログ出力し、区切り線でペアの区切りを分かりやすくしています。

```csharp
_subject1.OnNext(1); // 流れない
_subject2.OnNext(2); // next: 1.  >  next: 2.
```
`_subject1`に`1`が流れた時点では、まだ`_subject2`に値が1つも来ていないためペアが作れず、何も出力されません。`_subject2`に`2`が流れた瞬間、両方に値が1個ずつ揃うので`(1, 2)`がペアとして流れます。

```csharp
_subject2.OnNext(3); // 流れない
_subject2.OnNext(4); // 流れない
_subject1.OnNext(5); // next: 5.  >  next: 3.
```
ここがZipの理解の要になる部分です。`_subject2`にだけ`3`と`4`が続けて流れますが、`_subject1`側に対応する値がまだないため、どちらも出力されずにキューに溜まります。`_subject1`に`5`が流れた瞬間、`_subject1`側の値`5`と、`_subject2`側の**キューの先頭（先に来た`3`）**がペアになります。`4`ではなく`3`が使われる点に注意してください。

```csharp
_subject1.OnCompleted();
_subject2.OnCompleted(); // completed.
```
`_subject2`にはまだ`4`が未消費のまま残っていますが、`_subject1`が完了してこれ以上ペアを作れなくなった時点で、Zip全体も完了に向かいます。

## 実行結果の例
```
next.1
next.2
------------------------
next.5
next.3
------------------------
completed.
```

## よくあるつまずきポイント
- 「片方に複数回値が流れたら、最新の値とペアになる」と誤解しやすいですが、Zipは**先に流れた値（キューの先頭）**とペアになります。最新の値を使いたい場合はZipLatestを使います。
- `_subject2.OnNext(4)`が結果的に一度もログに出てこないことに驚くかもしれませんが、これは`_subject1`が先に完了してペアの相手がいなくなったためです。バグではなく仕様です。
- CombineLatestと違い、Zipは「両方に新しい値が1個ずつ揃うまで待つ」ため、片方だけが頻繁に値を出すような用途には向きません。
